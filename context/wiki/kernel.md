# Архитектура ядра Sclerotix: Трехавтоматная иерархия и зоны ответственности

По заветам Никлауса Вирта, Александра Степанова и теории типов Роберта Харпера, асинхронное ядро Sclerotix разделено на три изолированных автомата. Каждый автомат работает на своём математическом уровне, что гарантирует тотальный детерминизм логики и защиту от утечек и фрагментации памяти.

```text
[ Сырой поток TCP-сокета (Файл) ]
               │
               ▼
┌────────────────────────────────────────────────────────┐
│ АВТОМАТ №1: Парсер Заголовков (Line-Based Lexer)       │
│ Зона: Читает побайтово строго до двойного \r\n\r\n      │
└────────────────────────────────────────────────────────┘
               │
               ▼ Передача: (HTTP-Контекст, Каретка буфера)
┌────────────────────────────────────────────────────────┐
│ АВТОМАТ №2: Операционный Движок Тела (run_engine)      │
│ Зона: Управление I/O, Arena Buffer (ADR 0008),         │
│       регистрами длины и декрементами счетчиков.       │
│               │                                        │
│               ▼ (Поставка чистых сигналов NetworkInput)│
│ ┌────────────────────────────────────────────────────┐ │
│ │ АВТОМАТ №3: Чистый Затвор (next_state)             │ │
│ │ Зона: Математическое ядро (Иммутабельный DFA,     │ │
│ │       Тип-3 по Хомскому). Статическая таблица      │ │
│ │       переходов стейтов без побочных эффектов.    │ │
│ └────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

## 1. Автомат №1: Парсер заголовков (Построчный лексер)
* **Статус**: Первичный приемник потока.
* **Зона ответственности**: Работает в текстовом (ASCII) режиме. Выдергивает из сокета байты по одному, ищет логические терминаторы строк `\r\n`. Из полученных строк собирает HTTP-метод, путь запроса и словарь заголовков.
* **Точка остановки**: Как только автомат натыкается на пустую строку `\r\n\r\n` (маркер конца заголовков), он немедленно прекращает чтение и засыпает. Каретка чтения (указатель буфера) при этом останавливается строго на первом байте, который идет сразу за заголовками.
* **Результат**: Сформированный объект `HTTPRequestContext` и точный указатель на позицию в потоке.

## 2. Автомат №2: Операционный движок тела (`run_engine`)
* **Статус**: Внешняя мутабельная оболочка ядра (EFSM).
* **Зона ответственности**: Управляет физикой памяти и побайтовым движением каретки. Он получает эстафету от Автомата №1 и крутит цикл `while`. На каждом шаге он анализирует сетевой поток, вычисляет длины чанков или фиксированного тела, декрементирует счетчик оставшихся байт (`in_value`), отсекает служебные маркеры и пушит «мясо» данных в монолитный Arena Buffer (ADR 0008).
* **Результат**: Поставка атомарных, очищенных от физики сети сигналов (`NetworkInput`) на вход Автомату №3.

## 3. Автомат №3: Чистый Затвор (`next_state`)
* **Статус**: Внутреннее математическое ядро (Иммутабельный DFA).
* **Зона ответственности**: Чистый затвор, вложенный внутрь цикла Автомата №2. Он работает как изолированный процессор: принимает на вход пару `(State, NetworkInput)` и атомарно вычисляет следующую логическую вершину графа. 
* **Свойства**: Тотальный детерминизм, отсутствие побочных эффектов (никакого I/O, никаких мутаций памяти), полное рантайм-стирание типов регистров. Полностью верифицирован в nuXmv по LTL/CTL инвариантам безопасности.
