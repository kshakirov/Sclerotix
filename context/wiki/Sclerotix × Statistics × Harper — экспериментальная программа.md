# Sclerotix × Statistics × Harper

После стабилизации ядра **не оптимизируем его сразу**.

Сначала фиксируем текущую реализацию как **baseline** и снимаем экспериментальные данные до введения собственного streaming hash.

## Этап 1 — Baseline

На зафиксированной версии ядра:

- несколько независимых нагрузочных прогонов;
- latency / throughput;
- CPU;
- allocations;
- profiler;
- сохраняем сырые выборки, а не только агрегаты.

Это контрольная точка.

## Этап 2 — Собственный hashing

Меняем только механизм hashing маршрута:

```text
current hash
    ↓
streaming Sclerotix hash
```

Остальное ядро и условия эксперимента стараемся сохранить неизменными.

Повторяем те же нагрузочные серии и profiling.

## Этап 3 — Agnostic-Inference-Engine

Полученные выборки становятся реальным материалом статистического проекта.

Вопрос не просто:

> стало ли среднее меньше?

А:

> есть ли статистически различимое изменение распределения и имеет ли оно практически значимый размер?

Исследуем:

- распределения;
- разброс;
- latency tails;
- устойчивость эффекта между сериями;
- величину наблюдаемого эффекта.

## Этап 4 — Harper Abstract Board

Тот же эксперимент рассматриваем как цепочку физической реализации абстракции:

```text
выбор алгоритма hashing
        ↓
операции Python runtime
        ↓
objects / allocations
        ↓
CPU / memory behaviour
        ↓
latency / throughput
```

Это практический эксперимент по линии:

```text
абстракция → машинная цена
```

## Главное правило эксперимента

**Сначала baseline. Потом одно изменение. Потом повторное измерение.**

Не оптимизировать одновременно несколько частей системы.

Так Sclerotix становится экспериментальным стендом сразу для трёх направлений:

```text
Sclerotix
   │
   ├── Statistics → обнаружение и оценка эффекта
   │
   └── Harper     → объяснение физического происхождения эффекта
```

Первый кандидат на такой эксперимент — **собственный streaming hash маршрутизатора**.
