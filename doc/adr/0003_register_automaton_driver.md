# 📓 Шаг 0003: Операционный Автомат-Драйвер и Изоляция Регистров по Рейнольдсу

## 1. Анатомия Драйвера как Регистрового Автомата (EFSM)
Если ядро `transition` представляет собой чистый детерминированный автомат (DFA) с нулевой памятью, то окружающий его драйвер-магазин (`drive_automaton_magazine`) манифестирует себя как **Расширенный конечный автомат с регистрами (Register Automaton / EFSM)**.

Драйвер выполняет роль операционного моста между хаотичным сетевым потоком байт и строгой математической логикой ядра. Он оперирует локальным регистром данных:
* `current_values` — числовой регистр-счётчик, хранящий точный остаток байт текущей фазы протокола (Content-Length монолита или размер конкретного чанка) [1.1].

Драйвер реализует критически важную парадигму: **динамика входов и сбор сетевого контекста осуществляются строго ДО вызова функции вычислений**. Магазин подаёт патрон-сигнал в патронник до того, как затворная рама `transition` совершит прыжок на новые рельсы.

## 2. Изоляция инвариантов: Критика Record-based OOP
Традиционный подход к проектированию в Python подразумевает упаковку стейта в стандартные классы с приватными атрибутами (`self.__state`, `self.__current_values`). Однако, в динамической среде CPython инкапсуляция класса является лишь «соглашением джентльменов». Механизм `Name Mangling` легко обходится в рантайме снаружи через `_ClassName__variable`, что делает внутренние регистры уязвимыми для инвазивных мутаций и рушит верифицированные в `nuXmv` свойства безопасности.

Для нормализации понятий архитектура `Sclerotix` опирается на фундаментальную классификацию **Джона Рейнольдса (John C. Reynolds)**, разделившего объектные модели на два лагеря:
1. **Объекты как Записи (Record-based OOP)**: Модель стандартных классов (Python, Java, C++). Объект выражен как пассивная структура данных в памяти (словарь `__dict__`), методы которой работают со стейтом напрямую. Структура полностью прозрачна и уязвима для взлома.
2. **Объекты как Замыкания (Closure-based OOP)**: Модель, принятая в ядре `Sclerotix`. Объект — это **не данные, а чистое вычислительное поведение**. Объект выражен как набор процедур, лексически захвативших контекст переменных стека. 

## 3. Математический паттерн честного ADT (Abstract Data Type)
Реализация ядра `Sclerotix` полностью отказывается от классов в пользу лексических замыканий Рейнольдса, реализуя концепцию стирания типов (*Type Erasure*) Роберта Харпера. Данные физически изымаются из рантайма для внешнего наблюдателя, оставляя доступным исключительно функциональный интерфейс:

```python
def make_sclerotix_core_adt(initial_state, initial_values):
    # Локальные регистры навсегда изолированы в области видимости (лексическом стеке)
    _state = initial_state
    _values = initial_values

    def step(network_input):
        nonlocal _state, _values
        # Пинаем только чистую функцию переходов
        _state, _values, _ = transition(_state, _values, network_input)
        return _state

    def inspect():
        return _state, _values

    # Экспорт исключительно сигнатуры поведения — стейт стёрт для внешнего мира!
    return {
        "step": step, 
        "inspect": inspect
    }
```

Регистры автомата-склеротика защищены от мутаций не конвенциями программирования, а самой природой лексической области видимости интерпретатора CPython.
